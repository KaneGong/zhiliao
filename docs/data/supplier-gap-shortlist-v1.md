# 知料第一批供应商补库清单 v1

> 日期：2026-05-30
> 阶段：Formula Brief v1 数据线 / 第一轮补库
> 用途：把最影响当前 Formula Brief 演示质量的供应商缺口，转成可执行的补库与询样清单。
> 边界：本文件是内部执行与资料收集清单，不代表已经完成供应商验证，也不代表原料已确认适用于具体食品类别。

## 1. 本轮目标

本轮不追求覆盖全部行业原料，只优先补 3 个最影响当前产品演示和商业闭环的方向：

1. **儿童益生菌菌株**：当前平台暂无核心匹配，影响 GQ-003 和儿童营养场景可信度。
2. **GABA / 茶氨酸 / 睡前场景原料**：影响 GQ-001 和夜间场景软糖的原料事实、剂型适配与风味路线。
3. **透明质酸钠 / 胶原饮辅料**：影响 GQ-005 和女性轻负担胶原饮的法规边界、规格和风味遮蔽。

## 2. 补库优先级原则

| 优先级 | 处理标准 |
|---|---|
| P0 | 当前 Golden Questions 已出现、直接影响 Formula Brief 演示、且平台容易出现“暂无匹配”或信息过空 |
| P1 | 未来 2-3 周内很可能进入高频场景，但不阻塞当前演示 |
| P2 | 行业扩展方向，先记录，等合作伙伴和供应商线索明确后再补 |

## 3. 第一批 P0 补库清单

### SG-001 儿童益生菌菌株供应商

- **优先级**：P0
- **关联场景**：GQ-003、CASE-003、儿童营养 / 儿童益生菌固体饮料
- **当前问题**：Formula Brief 可以识别合规边界，但平台暂无核心菌株供应商匹配，只能停留在“概念建议”。
- **目标结果**：至少形成 2-3 家可联系的儿童益生菌供应商线索，且每家都能挂接到 `Supplier Spec Schema`。

**建议收集字段：**

| 字段 | 说明 |
|---|---|
| supplier_name | 供应商名称 |
| ingredient_name | 菌株名称与编号 |
| target_population | 适用年龄段，是否适合 3 岁以上儿童 |
| active_content | 活菌数规格（CFU） |
| dosage_form_fit | 适配固体饮料、条包、滴剂等 |
| stability_notes | 包埋/冻干技术、货架期稳定性 |
| food_category_statement | 适用食品类别声明 |
| required_docs | 规格书、COA、菌株身份证明、稳定性资料 |
| sample_available | 是否可寄样 |
| next_contact_action | 下一步动作：询样 / 索资 / 确认类别 |

**必须索取的资料包：**
- 菌株规格书
- COA
- 菌株身份证明 / strain identity
- 活菌数与稳定性资料
- 适用食品类别说明
- 推荐应用场景与剂型建议

**Formula Brief 使用价值：**
- 让“供应商匹配”从 0 变成可解释的 2-3 条线索
- 支持输出“建议向供应商索取哪些资料”
- 防止把不适合儿童的菌株乱推荐到儿童场景

### SG-002 GABA / 茶氨酸 / 睡前场景原料供应商

- **优先级**：P0
- **关联场景**：GQ-001、CASE-001、夜间轻负担软糖 / 睡前场景产品
- **当前问题**：平台能识别“助眠/改善睡眠”属于高风险表达，但缺少对 GABA、茶氨酸、Lactium 方向原料的系统资料整理。
- **目标结果**：形成“睡前场景原料包”清单，让 Formula Brief 在夜间场景里不仅能说概念，还能给出原料事实、风味挑战和补库状态。

**建议收集字段：**

| 字段 | 说明 |
|---|---|
| supplier_name | 供应商名称 |
| ingredient_name | GABA / 茶氨酸 / Lactium 等原料名称 |
| ingredient_category | 新食品原料 / 功能原料 / 乳来源原料等内部分类 |
| applicable_forms | 软糖、固体饮料、饮料等 |
| sensory_notes | 苦味、奶味、遮蔽难点 |
| process_fit | 是否适合软糖加热工艺、酸味体系 |
| regulatory_flags | 适用食品类别、每日摄入量、标签表达待复核点 |
| required_docs | 规格书、COA、公告/法规依据、应用建议 |
| sample_available | 是否可寄样 |
| next_contact_action | 索资 / 询样 / 工艺可行性确认 |

**必须索取的资料包：**
- 规格书与 COA
- 原料法规或公告依据
- 推荐添加量（若无法确认必须标记“待复核”）
- 软糖或固体饮料应用建议
- 风味遮蔽建议
- 稳定性或加工温度提示

**Formula Brief 使用价值：**
- 支撑“配方路线”部分解释为什么选该原料
- 支撑“合规检查”部分提醒哪些表达不能用
- 支撑“供应商匹配”部分区分已有线索与仍需补库的原料

### SG-003 透明质酸钠 / 胶原饮辅料供应商

- **优先级**：P0
- **关联场景**：GQ-005、CASE-005、女性轻负担胶原饮 / 口服美容场景
- **当前问题**：平台已有一定胶原蛋白供应商线索，但透明质酸钠、风味遮蔽、维 C 辅料等关键资料仍不完整。
- **目标结果**：形成“胶原饮关键辅料包”清单，让 Formula Brief 在美容场景里更像研发工具，而不是泛泛建议。

**建议收集字段：**

| 字段 | 说明 |
|---|---|
| supplier_name | 供应商名称 |
| ingredient_name | 透明质酸钠 / 胶原蛋白肽 / 维生素 C / 风味遮蔽辅料 |
| spec_name | 规格、分子量、纯度或活性信息 |
| dosage_form_fit | 瓶装饮料、条包、固体饮料等 |
| sensory_notes | 腥味、酸味、口感、清爽度 |
| regulatory_flags | 公告限量、强化范围、适用类别、直播话术风险 |
| required_docs | 规格书、COA、法规依据、应用案例 |
| sample_available | 是否可寄样 |
| data_completeness | 目前资料完整度 |
| next_contact_action | 下一步动作 |

**必须索取的资料包：**
- 规格书与 COA
- 透明质酸钠公告依据与适用范围说明
- 胶原饮推荐剂型与风味建议
- 腥味遮蔽或清爽口感案例
- 维 C 等辅料适用食品类别资料

**Formula Brief 使用价值：**
- 支持输出更真实的胶原饮路线与风味风险
- 防止把“美容养颜/锁水/抗氧化”当成普通食品可用声称
- 为后续供应商合作和样品验证留下明确入口

## 4. 每条线索进入平台的最低门槛

任何供应商线索在进入知料平台前，至少需要满足以下条件：

| 条件 | 要求 |
|---|---|
| 有稳定 ID | 能映射到 `supplier_id` 和 `ingredient_id` |
| 有基本资料 | 至少有供应商名、原料名、规格名称、required_docs |
| 有资料状态 | 明确 `data_completeness` 是 low / medium / high |
| 有下一步动作 | 明确是待询样、待补 COA、待确认食品类别还是待法规复核 |
| 不装成熟数据 | 缺资料时必须写“待补充”或“暂无平台匹配” |

## 5. 建议执行顺序

### 第一步：先做线索表，不急着求全

- 每个方向先整理 **2-3 家潜在线索** 或 **2-3 个待补原料节点**。
- 当前可以先允许“供应商待确认”，重点是先把字段框住。

### 第二步：按 Schema 录入最小字段

优先用 `data-intake-schemas-v1.md` 里的 `Supplier Spec Schema` 录入：
- supplier_id
- supplier_name
- ingredient_ids
- spec_name
- required_docs
- data_completeness
- next_contact_action

### 第三步：回写 Formula Brief 的数据状态

补库完成后，未来 Formula Brief 需要区分三种状态：
- **已有平台匹配**
- **有供应商线索，但资料不完整**
- **暂无平台匹配**
