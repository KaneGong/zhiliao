# Formula Brief v1 演示脚本 — P0 Golden Questions

> 日期：2026-05-30  
> 项目：知料 Formula Brief v1 上线前后商业验证  
> 用途：用 5 个 P0 golden questions 向研发、产品、法规、供应商和潜在付费方演示“食品研发 AI 工作台”的核心价值。

## 1. 演示定位

Formula Brief v1 的演示不应像普通聊天机器人展示“回答得很完整”，而应展示：

```text
新品想法 → 结构化 Product Brief → 多条配方路线 → 合规边界 → 供应商匹配 → Trust Score → 下一步打样/复核动作
```

### 演示目标

1. 让研发用户看到：它能形成可讨论的研发初稿。
2. 让产品/老板看到：它能把模糊想法变成内部立项材料。
3. 让法规/品控看到：它不会把风险表达包装成确定结论，而是标出边界和复核点。
4. 让供应商看到：AI 推荐可以嵌入真实新品需求，而不是做静态广告。

### 演示禁忌

- 不承诺“自动生成最终配方”。
- 不承诺“自动完成法规合规”。
- 不展示过多平台宏观功能，始终围绕 Formula Brief。
- 不让用户只看样例，尽量现场输入其真实需求。

## 2. 通用演示结构

### 2.1 30 秒开场

```text
知料现在的核心不是做一个食品行业 ChatGPT，而是做食品研发 AI 工作台。

我们先从一个最小闭环开始：用户输入新品想法，系统生成一份 Formula Brief，里面包括产品定位、配方路线、合规边界、供应商匹配、可信评分和下一步动作。

我接下来用 5 个典型食品研发问题演示，每个问题都不是看 AI 写得漂不漂亮，而是看它能不能变成可讨论、可保存、可找供应商的方案包。
```

### 2.2 每个场景固定讲法

1. **先讲业务背景**：这个需求为什么常见，真实工作里难在哪里。
2. **输入 golden question**：直接复制原问题。
3. **看 Product Brief**：系统是否理解产品类型、目标人群、剂型、成本、法规路径。
4. **看 Formula Routes**：是否给出保守/主流/创新等可比较路线。
5. **看 Compliance Checks**：是否标出普通食品/保健食品边界、禁用表达和复核点。
6. **看 Supplier Matches**：是否能导向样品、规格书、报价或资料获取。
7. **看 Trust Score 和 Next Steps**：是否知道哪里可信、哪里缺数据、下一步做什么。
8. **向观众提问**：这份方案哪块能直接进入你的工作流？哪块还不可信？

## 3. 场景一：GQ-001 助眠软糖 / 普通食品边界

### 输入

```text
开发一款面向办公人群的低糖助眠软糖，需要普通食品可用原料，风味温和，成本可控。
```

### 业务背景

助眠、放松、夜间场景是高需求方向，但“助眠/改善睡眠”容易触碰保健食品或药品化表达。这个场景适合展示知料的核心差异：不是只帮用户想卖点，而是在研发早期就提示普通食品表达边界。

### 演示顺序

1. **Product Brief**
   - 展示系统是否识别：办公人群、低糖软糖、夜间/放松场景、成本约束、普通食品路径。
   - 强调：把一句模糊需求变成内部可讨论 brief。

2. **Formula Routes**
   - 看是否提供低风险路线：风味体验、低糖胶基、舒缓场景原料。
   - 看是否区分 GABA、酸枣仁、褪黑素等原料的法规路径和风险。
   - 看是否提出成本可控的基础路线与差异化路线。

3. **Compliance Checks**
   - 重点展示：普通食品不能直接声称“助眠/改善睡眠”。
   - 展示禁用/不建议表达：助眠、改善睡眠、治疗失眠等。
   - 展示可替代表达：夜间轻负担、放松时刻、睡前仪式感、风味体验。
   - 展示需人工复核点：具体原料可用性、添加量、标签和详情页表达。

4. **Supplier Matches**
   - 展示低糖甜味体系、胶体、风味、可用营养/功能性原料供应商匹配。
   - 如果暂无匹配，要展示“暂无匹配”而不是编造供应商。

5. **Trust Score / Next Steps**
   - 展示法规风险如何拉低或影响评分。
   - 下一步应包括：确认普通食品可用原料清单、找供应商要规格书、打样低糖口感、复核宣传语。

### 要展示的价值点

- **合规可信价值**：系统不会迎合“助眠”需求乱写功效，而是主动改写成低风险表达。
- **研发效率价值**：从“想做助眠软糖”快速拆成剂型、甜味、风味、原料和打样问题。
- **产品沟通价值**：产品经理能拿可用表达和禁用表达与市场团队对齐。
- **供应商价值**：低糖体系、胶体、风味和相关原料供应商有机会进入早期方案。

### 演示追问

```text
如果你是研发/产品，这份方案里哪些内容可以直接进入立项讨论？
如果你是法规，哪些表达还需要更严格？
如果你是供应商，你希望自己的哪些资料出现在这个场景里？
```

## 4. 场景二：GQ-002 运动蛋白饮 / 成本与口感

### 输入

```text
做一款运动后恢复用的高蛋白饮料，目标人群是健身男性，希望口感清爽，蛋白含量有卖点，但成本不能太高。
```

### 业务背景

运动蛋白饮是市场清晰、供应链成熟但竞争激烈的场景。真实研发难点在于蛋白来源、蛋白含量、口感清爽、稳定性、成本之间的取舍。这个场景适合展示 Formula Routes 的多路线比较能力。

### 演示顺序

1. **Product Brief**
   - 展示目标人群：健身男性、运动后恢复场景。
   - 展示关键约束：高蛋白卖点、清爽口感、成本不能太高。
   - 看系统是否识别剂型：即饮饮料、乳饮、粉剂冲调或其他可能路径。

2. **Formula Routes**
   - 路线一：成本优先路线，例如乳清/牛奶蛋白与基础风味系统。
   - 路线二：口感优先路线，强调溶解性、清爽感、稳定性。
   - 路线三：差异化路线，例如植物蛋白复配或功能营养搭配，但提示口感和成本风险。
   - 重点展示每条路线的取舍，而不是给唯一答案。

3. **Compliance Checks**
   - 展示蛋白含量卖点、营养声称、运动恢复表达的风险边界。
   - 避免夸大“增肌”“恢复肌肉损伤”等高风险表达。
   - 提醒营养标签、蛋白含量、配料表和宣传语一致性。

4. **Supplier Matches**
   - 展示蛋白原料供应商、稳定剂/乳化体系、风味供应商。
   - 强调供应商资料价值：蛋白含量、溶解性、热稳定性、口感应用案例。

5. **Trust Score / Next Steps**
   - 下一步应包括：明确蛋白目标含量、确认成本区间、选择剂型、向供应商要样和应用建议、做口感稳定性测试。

### 要展示的价值点

- **路线决策价值**：研发可以快速比较成本优先、口感优先、差异化路线。
- **供应商匹配价值**：蛋白原料和应用方案高度依赖供应商资料，适合验证线索价值。
- **内部评审价值**：老板/产品能看到“为什么不能既高蛋白、清爽、低成本又极具差异化”。
- **数据补全价值**：如果 Trust Score 因供应商数据不足而降低，能推动供应商补资料。

### 演示追问

```text
你会优先打样哪条路线？
蛋白饮这个场景里，你最希望供应商提供什么资料？
如果这份方案节省了你前期找蛋白原料和应用资料的时间，它值多少钱？
```

## 5. 场景三：GQ-003 儿童益生菌 / 家长可理解但不踩线

### 输入

```text
开发一款儿童益生菌固体饮料，希望家长容易理解，主打肠道健康和日常营养支持，但不能踩保健食品声称风险。
```

### 业务背景

儿童益生菌是高关注、高风险、高供应商依赖场景。用户既想让家长听懂，又不能直接使用“调节肠道菌群、增强免疫”等保健声称。这个场景适合展示知料对“可理解表达”和“合规边界”的平衡。

### 演示顺序

1. **Product Brief**
   - 展示系统是否识别：儿童、益生菌、固体饮料、家长沟通、普通食品声称风险。
   - 强调儿童适用性和标签谨慎性。

2. **Formula Routes**
   - 路线一：日常营养支持路线，低风险表达。
   - 路线二：益生菌 + 益生元协同路线，提示菌株和添加量复核。
   - 路线三：口感/便利性路线，强调儿童接受度。
   - 看系统是否提示菌株可用性、活菌数、稳定性和储存条件。

3. **Compliance Checks**
   - 重点展示避免表达：调节肠道菌群、增强免疫、治疗便秘/腹泻等。
   - 展示可替代表达：日常营养补充、轻松冲调、适合儿童口味、膳食搭配支持等。
   - 提醒儿童食品、菌株名单、适用人群、标签表达、生产许可等复核点。

4. **Supplier Matches**
   - 展示益生菌菌株供应商、益生元、固体饮料代工/应用方案供应商。
   - 强调供应商必须提供菌株证明、稳定性数据、应用案例。

5. **Trust Score / Next Steps**
   - Trust Score 应清楚说明哪些判断来自已有数据，哪些需要供应商和法规人工确认。
   - 下一步：确认菌株法规可用性、添加量、活菌数、儿童标签表达、打样口感和稳定性。

### 要展示的价值点

- **风险控制价值**：把家长能懂的表达和保健声称边界分开。
- **供应商资料价值**：菌株证明和稳定性数据直接影响方案可信度。
- **销售验证价值**：益生菌供应商很可能愿意为精准场景曝光和线索付费。
- **用户侧价值**：产品经理可直接拿“可用/不建议表达”给内容团队讨论。

### 演示追问

```text
儿童益生菌这个场景，哪些表达你认为最容易踩线？
如果系统能把菌株证明和供应商资料挂在方案里，你会不会更愿意继续推进？
你认为益生菌供应商会为这样的推荐曝光付费吗？
```

## 6. 场景四：GQ-004 银发骨骼健康乳制品

### 输入

```text
做一款面向银发人群的骨骼健康乳制品，希望结合乳矿物盐、维生素D、蛋白质等原料，适合日常饮用。
```

### 业务背景

银发营养和骨骼健康有明确需求，但容易触碰疾病预防/治疗表达。乳制品剂型又涉及口感、营养强化剂适用范围、蛋白和钙协同。这个场景适合展示知料处理“营养逻辑 + 法规限制 + 剂型落地”的能力。

### 演示顺序

1. **Product Brief**
   - 展示目标人群：银发人群。
   - 展示剂型：乳制品/乳饮/发酵乳/营养奶等可能路径。
   - 展示核心诉求：骨骼营养、日常饮用、蛋白质、钙、维生素 D。

2. **Formula Routes**
   - 路线一：高钙 + 蛋白基础路线，强调日常营养。
   - 路线二：乳矿物盐 + 维生素 D 协同路线，提示营养强化剂限制。
   - 路线三：银发友好路线，考虑低糖、易饮、口感和消化接受度。
   - 看是否说明原料角色：钙来源、维 D 促进钙吸收相关营养逻辑、蛋白支持日常营养。

3. **Compliance Checks**
   - 重点展示：不能表达治疗骨质疏松、预防骨折、改善疾病。
   - 提醒营养强化剂适用食品类别、添加量、标签声称条件。
   - 展示普通食品可用表达：骨骼营养支持、高钙、蛋白质来源等需符合标准条件的表达。

4. **Supplier Matches**
   - 展示乳矿物盐、维生素 D、蛋白原料、乳制品应用方案供应商。
   - 强调供应商需提供适用食品类别、规格、检测和应用稳定性资料。

5. **Trust Score / Next Steps**
   - 下一步：确认产品类别、营养强化剂适用范围、目标营养成分含量、感官测试、标签表达复核。

### 要展示的价值点

- **专业研发价值**：不只是列原料，而是解释钙、维 D、蛋白在乳制品中的协同逻辑。
- **法规边界价值**：把营养支持和疾病治疗表达清楚分开。
- **适老化产品价值**：提示银发人群对糖、口感、饮用便利性和消化接受度的要求。
- **供应商价值**：乳矿物盐、维 D 和乳蛋白供应商可通过应用资料提升匹配概率。

### 演示追问

```text
这份方案是否足够支持一次内部立项讨论？
银发乳制品里，你最担心法规、口感还是成本？
如果供应商能补充适用类别和应用案例，会不会提高你对方案的信任？
```

## 7. 场景五：GQ-005 女性美容胶原饮

### 输入

```text
做一款女性美容方向的胶原蛋白饮，想突出皮肤状态、光泽感和轻负担，渠道主要是小红书和直播电商。
```

### 业务背景

女性美容胶原饮非常适合内容渠道，但“美容养颜、改善皮肤、抗衰”等表达风险高。小红书和直播电商还涉及内容话术放大风险。这个场景适合展示知料对渠道表达和声称风险的判断。

### 演示顺序

1. **Product Brief**
   - 展示目标人群：女性、内容电商用户。
   - 展示剂型：胶原蛋白饮、即饮/粉剂/浓缩饮等可能方向。
   - 展示核心卖点：皮肤状态、光泽感、轻负担、渠道表达。

2. **Formula Routes**
   - 路线一：胶原蛋白基础路线，强调口感和日常饮用。
   - 路线二：胶原 + 维 C 或其他营养搭配路线，提示声称边界。
   - 路线三：轻负担内容友好路线，强调低糖、风味、包装和场景。
   - 看是否区分透明质酸、胶原蛋白、维 C 等原料路径和限制。

3. **Compliance Checks**
   - 重点展示高风险表达：美容养颜、改善皮肤、抗衰、淡斑、美白、修复等。
   - 展示普通食品可用表达：日常营养补充、轻负担饮用、风味与生活方式表达、保持好状态等更谨慎措辞。
   - 直播/小红书风险：达人话术、评论区引导、前后对比、暗示功效。

4. **Supplier Matches**
   - 展示胶原蛋白、维 C、透明质酸、风味、代工厂或包装供应商匹配。
   - 强调供应商应用案例、口感遮蔽、稳定性和合规资料的重要性。

5. **Trust Score / Next Steps**
   - 下一步：确认原料法规路径、内容渠道话术白名单/黑名单、样品口感、目标成本、供应商证明文件。

### 要展示的价值点

- **渠道合规价值**：不仅看配方，也看小红书/直播话术风险。
- **产品表达价值**：帮助产品和内容团队把“想说的卖点”改写成更稳妥的表达。
- **供应链价值**：胶原、透明质酸、维 C 和代工应用方案都能自然进入 Supplier Matches。
- **商业验证价值**：该场景容易让品牌方和供应商都看到实际使用场景。

### 演示追问

```text
如果你负责小红书/直播，这份可用表达和不建议表达是否能直接给内容团队？
你最希望系统补充哪类证据：法规、竞品、原料资料还是平台规则？
胶原/透明质酸供应商会不会愿意为这类精准场景曝光付费？
```

## 8. 面向不同对象的讲解重点

| 对象 | 重点讲什么 | 不必展开什么 | 关键追问 |
|---|---|---|---|
| 研发工程师 | Formula Routes、原料角色、工艺/口感、打样下一步 | 商业模式、投资人愿景 | 哪条路线能打样？缺什么数据？ |
| 产品/品类经理 | Product Brief、卖点、可用表达、内部评审材料 | 技术实现细节 | 能否拿去开立项会？ |
| 法规/品控 | Compliance Checks、禁用表达、人工复核点、Trust Score | 供应商年费 | 哪些判断不够严谨？ |
| 创始人/老板 | 时间节省、方案包、导出、团队协作、付费价值 | 单个原料细节 | 这能不能缩短新品前期周期？ |
| 供应商销售 | Supplier Matches、线索字段、曝光统计、询样动作 | 前端交互细节 | 什么线索值得付费？ |
| 供应商应用工程师 | 原料适配、应用方案、规格书、案例资料 | 投资故事 | 你的资料怎样才能提高匹配？ |

## 10. 演示成功判断

### 用户侧强信号

- 用户愿意提供真实新品需求。
- 用户问能否保存、导出、分享给同事。
- 用户开始纠正细节，而不是泛泛评价。
- 用户说“这个可以拿去和老板/研发/供应商讨论”。
- 用户愿意 7 天后再用一次。

### 供应商侧强信号

- 供应商主动问推荐逻辑和资料如何影响排名。
- 供应商愿意提供规格书、应用方案或样品政策。
- 供应商问能否看到曝光次数、询样线索和用户需求。
- 供应商能说出一个有效线索值多少钱。
- 供应商愿意进入 3000/8000/20000 年费讨论。

### 需要 Kane 现场判断的点

1. AI 输出中的原料建议是否存在明显行业硬伤。
2. 每个 golden question 是否代表真实高频需求，还是需要替换为 Kane 更熟的品类。
3. 哪些表达在真实销售/电商场景中仍然偏冒险。
4. 哪些供应商匹配最有商业机会。
5. 哪个场景最适合做第一条公开案例或演示视频。
