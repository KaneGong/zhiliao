# 知料平台发展战略方案

> 2026-05-26 | 当前状态：正式上线公测，94 种原料，71 条法规，8 家供应商

---

## 一、平台推广策略

### 核心判断

知料是典型的 B2B 利基产品 — 用户群窄但需求确定、决策理性、信任门槛高。C 端的"裂变""病毒传播"不适用。推广的核心逻辑是：**在目标人群聚集的地方，用专业内容证明产品价值，让早期用户成为传播节点**。

两个用户群的需求完全不同：

| | 食品企业研发/PM | 原料供应商 |
|---|---|---|
| 核心诉求 | 缩短研发周期、降低合规风险 | 让更多配方用到自己的原料 |
| 决策逻辑 | "这东西能不能真正省我时间？" | "这平台能不能给我带来客户？" |
| 接触渠道 | 行业群、公众号、同行推荐 | 行业展会、已有商务关系 |
| 付费意愿 | 中等（需验证价值） | 高（如果有获客效果） |

### 方案：分三阶段推进

**第一阶段：冷启动（第 1-2 周）— 目标：10-20 个种子用户**

1. **微信朋友圈 + 行业群定向推送**
   - 不是发"知料上线了"，而是发一个具体的场景演示
   - 录 15 秒 AIDemo 动图，配文："做一款助眠软糖，从原料筛选到 GB 2760 合规检查，30 秒出方案。食品研发的效率工具，免费试用。"
   - 发给 5-10 个食品行业群
   - 关键：链接指向推荐页，让用户进来就能直接试用，不需要注册

2. **现有供应商激活**
   - 8 家供应商是你的第一批"地推团队"
   - 给他们发邮件/微信："知料平台已上线，您的原料数据已入库。品牌方搜索相关功能原料时，AI 会自动推荐您的产品。建议您登录完善资料，提升推荐权重。"
   - 供应商为了获客会主动帮你在行业内传播

3. **注册引导**
   - 目前"无需注册直接使用"是对的，但需要一个轻量转化点
   - 在 AI 生成方案后加一句："注册后可以保存方案、追踪原料合规变更、接收行业法规更新推送"
   - 用户拿到有价值的方案后，注册意愿最高

**第二阶段：内容传播（第 3-4 周）— 目标：100+ 试用用户**

4. **行业媒体投稿**
   - 写一篇"AI 辅助食品配方研发实测报告"
   - 结构：真实场景（开发一款功能性饮料）→ 传统流程（翻手册、查法规、联系供应商，3-5 天）→ 知料流程（输入需求，30 秒出完整方案含合规分析）→ 数据对比
   - 投稿渠道：食品伙伴网、食研汇、Foodaily 每日食品、FBIF
   - 这些号对"AI+食品"选题需求大，过稿率高

5. **知乎/小红书专业内容**
   - 知乎："食品研发中 AI 工具能替代多少人工？" — 以从业者身份写回答，自然带出知料
   - 小红书："食品研发人的效率神器" — 截图 + 使用场景，打"食品研发""功能食品"标签

**第三阶段：生态扩展（第 5-8 周）— 目标：50+ 供应商，500+ 注册用户**

6. **供应商定向招募**
   - 从阿里巴巴 1688 食品添加剂/原料类目找到 TOP 供应商
   - 邮件模板："您的原料出现在 300+ 食品企业的配方推荐中 — 知料 AI 平台供应商免费入驻"
   - 供应商进来后，原料库数据会自然增长，平台推荐质量也随之提升

7. **行业展会合作**（FBIF、FIC 等）
   - 如果参加展会，带一台 iPad 现场演示
   - "输入你们公司正在研发的产品方向，30 秒看出配方框架" — 极强的展位引流效果

### 关键数据指标

- 首页访问 → 试用（输入查询）：> 40% 转化率是健康的
- 试用 → 注册：> 15%
- 注册 → 留存（7 天内回访）：> 30%

## 二、AI 推荐内容优化方案

### 核心判断

当前 AI 推荐的底层是 DeepSeek API + 系统提示词 + 94 条原料数据。问题是：**模型对食品科学的深层知识有限，推荐逻辑依赖 prompt 工程，缺少结构化的配方知识库支撑**。

真正提升推荐质量需要三层：

### 方案：三层知识体系

**第一层：结构化配方知识库（立即可做）**

目前原料数据只有名称和基本属性。需要补充三个维度：

1. **原料协同矩阵**
   - 记录哪些原料组合有协同增效（如：褪黑素 + GABA 协同改善睡眠、维生素 C + 铁 促进吸收）
   - 数据来源：PubMed 文献综述、食品科学教科书、已有产品配方分析
   - 实现方式：在 `ingredients.json` 中增加 `synergies` 字段
   ```json
   {
     "name": "褪黑素",
     "synergies": [
       {"ingredient": "GABA", "effect": "协同改善入睡时间", "evidence": "中等"},
       {"ingredient": "酸枣仁提取物", "effect": "传统配伍，安神增效", "evidence": "传统"}
     ]
   }
   ```

2. **功能分类体系**
   - 目前用 tags（2 个标签）太粗。建立功能分类树：
   - 一级：睡眠改善、免疫调节、运动营养、肠道健康、美容抗衰、儿童营养...
   - 二级：每个一级下细分（如睡眠→入睡困难/睡眠维持/昼夜节律调节）
   - 用户输入"助眠"时，AI 不仅匹配关键词，还匹配功能分类下的所有原料

3. **添加量参考数据库**
   - 每个原料记录：法规允许范围、行业常用范围、文献推荐范围
   - 来源：GB 标准、供应商产品手册、已上市产品标签

**第二层：全球配方案例库（1-2 周搭建）**

从公开渠道收集真实产品配方作为参考：

4. **已上市产品逆向分析**
   - 在天猫/京东搜索功能食品，从产品标签提取配方组成
   - 例：汤臣倍健褪黑素片 → 褪黑素 2.5mg + VB6 1.5mg
   - 这些是"经过市场验证的配方"，比 AI 凭空生成的可靠
   - 存储为 `recipes.json`，AI 推荐时作为参考而非直接复制

5. **PubMed/Google Scholar 文献检索**
   - 针对每种原料，搜索近 5 年的临床研究
   - 提取：有效剂量范围、协同原料、安全性数据
   - 不确定的信息标注"文献来源：[DOI]，证据等级：初步/中等/充分"

**第三层：Prompt 工程优化（持续迭代）**

6. **当前 prompt 的问题**
   - 需要审查 `src/app/api/ai-recommend/prompt.ts` 和 `route.ts` 中的系统提示词
   - 关键优化方向：
     - 要求 AI 区分"法规明确允许"和"法规未禁止"
     - 要求给出推荐理由而非仅列出原料
     - 要求标注信息确定性（"确定/大概率/需进一步确认"）
     - 多方案对比："方案 A（成本优先）、方案 B（功效优先）、方案 C（创新优先）"

### 实施优先级

1. 🔴 本周：审查并优化 prompt → 立即提升输出质量
2. 🟡 下周：补充原料协同矩阵和添加量数据 → 提升推荐精准度
3. 🟢 本月：搭建配方案例库 → 提供"有据可查"的参考

## 三、法规数据库完善方案

### 核心判断

71 条法规对于一个食品合规 AI 来说远远不够。但关键不在于"把所有法规都塞进去"，而是 **AI 要知道什么时候该引用哪条法规、并正确解释法规的适用条件**。

食品法规的特点：层级多（法律→标准→公告）、更新频繁、适用条件复杂（同一原料在不同食品类别中规定不同）。

### 方案：法规知识体系分层建设

**第一层：现有法规结构化（当前 71 条）**

当前的 `regulations.json` 需要从"条文存储"升级为"可推理的知识"：

1. **法规数据模型重构**
   ```json
   {
     "id": "GB-2760-2024",
     "title": "食品安全国家标准 食品添加剂使用标准",
     "type": "国家标准",
     "scope": ["食品添加剂"],
     "effective_date": "2025-02-08",
     "source_url": "https://...",
     "key_provisions": [
       {
         "substance": "褪黑素",
         "category": "保健食品原料",
         "status": "允许使用",
         "conditions": "仅限保健食品，不得用于普通食品",
         "max_dosage": null,
         "notes": "作为保健食品原料，添加量需符合产品注册/备案要求"
       }
     ]
   }
   ```
   - 每条法规下的具体规定拆分为独立记录，让 AI 可以精确匹配
   - `conditions` 字段特别重要 — 法规的适用条件往往是关键

2. **补充缺失的核心法规**（至少补充以下 20+ 条）
   - GB 2760-2024 食品添加剂使用标准（已有部分）
   - GB 14880-2012 食品营养强化剂使用标准
   - GB 7718-2011 预包装食品标签通则
   - GB 28050-2011 预包装食品营养标签通则
   - GB 16740-2014 保健食品良好生产规范
   - GB 29922-2013 特殊医学用途配方食品通则
   - GB 24154-2015 运动营养食品通则
   - 《保健食品注册与备案管理办法》
   - 《新食品原料安全性审查管理办法》
   - 新食品原料目录（动态更新）
   - 药食同源目录
   - 保健食品原料目录

**第二层：法规推理能力（重要！）**

光有法规条文不够，AI 需要理解法规的推理逻辑：

3. **法规冲突/优先级规则**
   - 特殊规定优先于一般规定（如保健食品标准优先于普通食品标准）
   - 新标准优先于旧标准
   - 强制性标准优先于推荐性标准
   - 在 prompt 中明确这些优先级规则

4. **法规不确定性处理**
   - "法规明确规定" → 直接结论
   - "法规未明确禁止但无先例" → 标注"需咨询监管部门"
   - "法规条款存在争议解读" → 附带不同解读和来源

**第三层：法规更新追踪**

5. **定期更新机制**
   - 国家卫健委、市场监管总局网站每周检查新公告
   - 关键源：https://sppt.cfsa.net.cn:8088/（食品伙伴网法规数据库）
   - 每次 AI 推荐时，在 prompt 末尾加上"最近 3 个月的法规更新提醒"

### 实施优先级

1. 🔴 本周：补充 20+ 核心法规的 key_provisions 结构化数据
2. 🟡 下周：建立法规推理规则（优先级、适用条件）
3. 🟢 持续：监控法规更新

## 四、AI 幻觉规避与创造力平衡

### 核心判断

这是最棘手也最重要的问题。B2B 场景下，**一次幻觉可能毁掉全部信任**。但完全约束 AI 的创造力，又会让推荐变成"百度百科摘要"，失去价值。

关键洞察：**用户要的不是"AI 的正确率 100%"，而是"我知道该信哪部分，该验证哪部分"**。

### 方案：六层防幻觉体系

**第一层：强制溯源**

1. **每条推荐必须有依据**
   - 原料推荐 → 标注来源（GB 标准编号 / 供应商产品手册 / 文献 DOI）
   - 添加量推荐 → 标注参考范围来源
   - 合规判断 → 明确引用的法规条款号
   - 无法溯源的信息 → 标注"基于 AI 推理，建议验证"

2. **在 AI 回答中加入可信度标签**
   ```
   ✅ 法规明确允许 — 褪黑素可作为保健食品原料（GB 16740）
   ⚠️ 法规未禁止，建议确认 — 褪黑素软糖中褪黑素释放速率标准暂无明确规定
   💡 AI 推理建议 — 考虑搭配 GABA 协同改善睡眠（文献支持，非法规要求）
   ```

**第二层：约束提示词**

3. **系统提示词强化**
   - "你的首要原则是不提供未经证实的信息。如果某个说法没有明确的法规或文献依据，必须明确标注为推测。"
   - "对于添加量，如果法规有明确规定，引用法规；如果没有，说明行业惯例范围并标注'非强制性'。"
   - "绝对禁止编造 GB 标准编号、文献出处、或企业产品信息。"

**第三层：数据围栏**

4. **RAG 模式优先**
   - AI 推荐时必须先检索本地原料库和法规库
   - 只推荐数据库中存在的原料（不凭空发明）
   - 法规判断以本地法规库为准，模型知识作为补充参考
   - 实现方式：在 API route 中先执行数据检索，将结果注入 prompt

**第四层：配方合理性校验**

5. **交叉验证规则**
   - 添加量是否在法规允许范围内？
   - 原料组合是否在功能和法规上都合理？
   - 剂型是否与原料特性匹配？
   - 这些校验在 prompt 中作为"自检清单"要求 AI 逐项检查

**第五层：创造力安全边界**

6. **创新 ≠ 编造**
   - 创新配方思路的来源：已有文献中的原料组合 × 不同产品形态 × 目标人群适配
   - 例："褪黑素 + GABA 在保健品中常见 → 在软糖剂型中的创新应用 → 针对年轻白领睡眠场景的差异化配方"
   - 这是"组合创新"而非"凭空创造"，每一步都有据可查

7. **多方案对照**
   - 每次输出 2-3 个方案：保守方案（完全按法规标准）、主流方案（参考市场现有产品）、创新方案（文献支持的新组合）
   - 让用户看到"创新的代价和依据是什么"

**第六层：用户认知设计**

8. **在 UI 层面建立信任**
   - 方案顶部：数据来源概览（"本方案引用了 3 条国标、5 种原料数据、2 篇文献"）
   - 每条推荐的末尾：可点击的溯源链接
   - 底部免责声明（简短有力）："知料提供依据和方向，最终配方决策由专业研发人员完成。标注为'AI 推理'的内容建议验证后使用。"

### 实施优先级

1. 🔴 本周：优化系统提示词（第三层 + 第五层部分）
2. 🔴 本周：在 UI 中加入可信度标签（第一层 + 第六层）
3. 🟡 下周：实现 RAG 模式（第四层）
4. 🟡 下周：添加配方合理性校验规则（第五层）
5. 🟢 本月：原料协同矩阵和配方案例库（支撑第四层）
